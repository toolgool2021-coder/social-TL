14 ноября 2026. Источник — полный текст, присланный пользователем в разговоре. Это сравнение исходных файлов, не независимое чтение активного Firebase release.

## Сохранённый исходник

- [Точный присланный файл](firestore-3.0.user-supplied.rules), без редактирования.
- SHA-256: `1fc2f1258c35df28f520592f83c73ea2e851607096334628a1900839aa687b6b`.
- Размер: 17 547 байт; 701 перевод строки, около 702 строк в редакторе. Из них 104 пустые строки и 62 строки комментариев.
- Проект/время последней публикации/ruleset ID не предоставлены. Для фактического отката необходимо убедиться, что это действующая версия, либо получить свежий экспорт.

## Почему новый файл был короче

Предыдущая запись кандидата занимала 261 строку: функции, массивы и условия были компактными. Ни один целевой match-раздел исходника не пропал. Для удобства проверки кандидат теперь развёрнут на 571 строку: по одному условию/элементу списка на строку, с раскрытыми функциями. Количество строк не было целевым ограничением.

До и после этого форматирования совпадают все 3 718 токенов кода, включая строки и регулярные выражения. Функциональные изменения относительно старой версии перечислены ниже — форматирование не добавило новых изменений.

## Реальные изменения поведения

| Сценарий | Старые правила | Кандидат |
| --- | --- | --- |
| Обычный текст из текущего chats.html с `sticker: ""` | Отклоняется: присутствующий sticker требует длину ≥1 даже для текста | Разрешён для text; для sticker требуется непустое значение |
| Проверка отсутствующего нового чата его участником | Отказ из-за отсутствующего resource.participants | Разрешена проверка ID с UID участника; существующие чаты доступны только их участникам |
| Запись реакции | Участник может заменить legacy-карту, включая чужие реакции | Только собственный документ, допустимый emoji и существующее сообщение |
| Прочтение сообщения | Получатель может подставить произвольное readAt и переписывать его | Однократно, серверное время; отсутствие поля и legacy null поддерживаются |
| Время новых записей/изменений | Многие значения не проверяются | Новые createdAt и изменяемые updatedAt/editedAt/reviewedAt проверяются против request.time |
| Bio/URL профиля, изменяемый imageUrl поста | Часть полей не проверяется | Валидация новых/изменяемых значений; пустые профильные URL разрешены |
| Некорректное неизменяемое legacy-поле профиля | Может мешать изменению других полей | Проверяются изменённые поля; существующие привилегии сохраняются |
| Сохранение удалённого поста | Допускается | Запрещено; повторное сохранение существующего поста остаётся доступно |
| Комментарий к отсутствующему посту | Допускается | Запрещён |
| Новый произвольный ID/порядок участников чата | Допускается | Новый чат требует сортированный список и канонический ID |
| Ответ/редактирование сообщения | Часть значений не проверяется | Лимиты replyTo/replyText, серверное editedAt, непустое редактирование text |

Текущие клиенты используют serverTimestamp() для соответствующих записей. Это не гарантия для всех старых опубликованных клиентов или неизвестных коллекций.

## Что не переносится автоматически

- Старые reaction maps остаются в документах, однако новый клиент их не отображает и не редактирует. Нужна отдельная контролируемая миграция, если требуется сохранить отображение старых реакций.
- Существующие неканонические чаты доступны участникам по правилам. Текущий UI вычисляет канонический ID, поэтому автоматического открытия/объединения произвольных старых ID нет. Кроме того, при отправке он записывает сортированных participants; это может конфликтовать со старыми несортированными участниками и в старых, и в новых правилах. Проверить реальные записи до выпуска.
- Ни старые, ни новые правила сами по себе не реализуют уникальность username, приватные аккаунты/посты, блокировки, Assistant, опросы, upload/Storage или управление стикерпаками.
- Развёртывание правил не разворачивает Cloud Functions.

## Автоматическая проверка

`tests/firestore.migration.test.mjs` загружает **обе** реальные версии в отдельные demo-проекты одного эмулятора. Проверяет все match-пути, сохранённые разрешённые сценарии аккаунтов/социальных действий/чата/владельца, отказ посторонним и самоповышению, штатный text payload, отсутствующий чат, подделку реакций/прочтения, timestamps/URL, канонические и legacy-чаты и сохранность legacy-данных при редактировании.

```bash
npm run test:rules
```

Это поведенческие тесты правил, не браузерный end-to-end и не проверка активного production release. Внедрение выполняется по [плану Firebase](../../NEXORA_3_2_FIREBASE.md).
